### Migration 0008-provision-learner — the shape that matters <!-- project: github.com/ronslink/hatoove -->

- `SECURITY DEFINER` plpgsql `provision_learner(user_id text, allowance integer)`, owned by the
  MIGRATION role, `SET search_path = "<schema>", pg_catalog`, idempotent (swallows
  `unique_violation`, never overwrites an existing allowance).
- `REVOKE ALL ... FROM PUBLIC` then `GRANT EXECUTE ... TO "<auth>"` only. Because FORCE RLS
  applies even to the definer, the file also adds an INSERT policy `provision_learner_insert`
  `FOR INSERT TO CURRENT_USER WITH CHECK (true)` (CURRENT_USER = migration role at create time;
  auth role matches no policy and holds no INSERT → its direct insert is refused).
- Proof pair required: auth role CANNOT `INSERT` into `entitlements` directly, but CAN through
  the function. A leg proving only the function works misses the point.
- Because `0008` is the first migration to exercise MFP-01's contract, must confirm
  `node server/migrate.mjs` applies it AND a second run applies nothing.
- Check `tools/table-class-check.mjs` classifies any table added (none added here — function, not
  table — but read its rules before assuming the policy/function is exempt).
  <!-- project: github.com/ronslink/hatoove -->
