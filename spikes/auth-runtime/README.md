# Local auth/runtime spike

PRE-05 / F-03, contract [0.1.0](../../docs/contracts/PILOT-V0.1.md). This is a source-only experiment with real PostgreSQL transactions and synthetic records. It does not alter or start `server.js`, serve the learner UI, read `.env`, contact an AI/email/payment provider, or provide a production entrypoint.

Use a separate source-only checkout. Node >=22.16; tested locally on Node 24.4.1. Better Auth 1.7.6, pg 8.23.1 and transitive dependencies are locked. No root-package dependency changes.

From the repository root, provision only the dedicated fixture container:

```text
docker run --name hatoove-pre05-db --label hatoove.execution=pre05-local -e POSTGRES_DB=hatoove_spike -e POSTGRES_HOST_AUTH_METHOD=trust -p 127.0.0.1:55435:5432 -d postgres:17-alpine
npm ci --prefix spikes/auth-runtime --ignore-scripts --no-audit --no-fund
node --test spikes/auth-runtime/test.mjs
docker stop hatoove-pre05-db
```

The loopback-only container uses trust solely for disposable synthetic testing. It has no source bind mount or production data. Do not reuse another database or expose its port. If the name/port is occupied, inspect the known fixture container; do not stop another application's service. PostgreSQL must be ready before testing (`docker exec hatoove-pre05-db pg_isready -U postgres -d hatoove_spike`). Retire this named container when its evidence is complete; never apply these settings to production.

Tests use random `spike_<hex>` schemas and clean only their own schema in `finally`. `auth-schema.sql` is generated by the pinned library's `getMigrations().compileMigrations()` on an empty schema. Every run compares that output and checks a second migration is empty. Production needs separately reviewed SQL migration history, roles and RLS. No runtime auto-migration is proposed.

Checks exercise two accounts, request ownership, Origin rejection, competing draft revisions, immutable submission, transactional failure, concurrent idempotency, revoked sessions, second-session resume, lease fencing, exhausted retries, allowance reservation, rollback of completion, reopening feedback and deletion precedence. Fixture feedback has no scores. Repeated provider calls/spend, real content/audio, real-device behavior, security signoff and production readiness are not established.
