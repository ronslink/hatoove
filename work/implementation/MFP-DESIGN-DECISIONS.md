## R11: the data contract must match the displayed criteria

At the pinned base, `public/js/ai.js:760–765` defines four internal criteria: `aufgabe` 15, `kommunikation` 10, `richtigkeit` 12 and `ausdruck` 8. Its prompt also requests a total, pass-like bands and Boolean Leitpunkt coverage. These are legacy behavior to retire, not a validated scoring contract to copy into the worker.

The repository's **unreviewed** [telc draft](../../docs/exam/telc-b1-written-draft.json) and [source register](../../docs/exam/TELC-B1-SOURCES.md) instead describe Aufgabenbewältigung, Kommunikative Gestaltung and Formale Richtigkeit. The design's three rows do not resolve the discrepancy or establish educational approval.

MFP-06b owns the server prompt, structured schema and version binding; MFP-08 owns the matching rendering. Resolve R11 before finalizing that result contract. Other shell, font, task-list and asynchronous-state work can proceed against explicit fixtures meanwhile. If three criteria are selected, add a distinct rubric/prompt version, validated criterion IDs and grade bands, fixtures for malformed/missing/duplicate criteria, and human review under E-01/C-05. Vocabulary advice may remain explanatory text without creating a fourth scored criterion. Never renormalize 15/10/12/8 into three grades.

If provisional four-criterion feedback is selected, label it as internal practice feedback, keep its rubric `unreviewed`, and implement R15 independently. Any stored result keeps its original submission, criterion IDs, rubric/prompt/model versions and explanation language. History renders the saved version with an honest label; unsupported older result shapes get a clear compatibility message rather than a fabricated conversion. A changed rubric applies to new assessments only; revisions remain linked to their originals.

The four required content points may be shown as neutral task instructions or learner-controlled planning checks, never automatic correctness ticks. Do not claim two independent model checks. Pending, failed, malformed or absent assessments have no grades; failure stays `Unbewertet` with preserved writing.

## Asset and CSS foundation within MFP-07a

Read-only audit of `D:/B1_Prep/design` reproduced all **22 manifest hashes** at the pinned base. It found 14 English-root HTML screens, 112 inline style attributes across those screens (four more in the index), only 1100/860 px width breakpoints and no reduced-motion rule. The writing screen's inline two-column grid also overrides the media rule intended to collapse it. This is source evidence, not rendered evidence.

The two **specific supplied font subsets** have 231 mapped codepoints (Source Sans 3) and 226 (Bricolage Grotesque). Neither supplies Cyrillic or Arabic letters; both miss `ĞğİŞş` while containing `ı`. This is not a claim that the full font families lack those languages. Both embed an OFL URL, but the design folder includes no standalone licence text. Their bytes match the existing `hatoove-site/dist/assets/` copies, which already include `OFL-SourceSans3.txt` and `OFL-BricolageGrotesque.txt`; curate those matching notices with the original fonts after checking provenance.

A suitable candidate is a Cyrillic/Latin-extended Noto Sans build plus Noto Sans Arabic for explanation blocks, while retaining licensed branding fonts where appropriate. Use [Noto usage guidance](https://notofonts.github.io/noto-docs/website/use/), [Noto Sans coverage](https://notofonts.github.io/noto-docs/specimen/NotoSans/), and the actual [Latin/Cyrillic](https://github.com/notofonts/latin-greek-cyrillic/blob/main/OFL.txt) and [Arabic](https://github.com/notofonts/arabic/blob/main/OFL.txt) licence sources. Pin the source/version/hash of each imported font and its notice. Family names alone do not establish coverage.

MFP-07a must:

1. Curate only needed assets into `public/assets/design/`; version provenance/licences and a reusable token/component stylesheet. Do not import the live install or run its builder.
2. Extract the reference's presentational inline styles into shared classes/tokens. Define any exceptional dynamic custom properties explicitly; don't weaken the gate simply to accept the import.
3. Retarget `tools/design-check.mjs` to the new client and prove it detects violations of the adopted rules, including missing reduced motion, raw design values, broken German-language invariance and unapproved inline presentation. **The existing check does not scan the reference HTML or prohibit every inline style**; its corner-radius rule only warns. This is a new scoped acceptance rule, not 112 already-failing repository checks.
4. Add reduced-motion behavior, visible focus and layouts proven at 320/390, 768/1024/1180 and 1440 px, both themes, with keyboard navigation and text zoom. Choose breakpoints from observed fit; a breakpoint count alone proves nothing.
5. Verify actual font cmap coverage and rendered Ukrainian/Turkish strings and Arabic shaping, punctuation and mixed German examples. Scope `lang`/`dir=rtl` to Arabic explanations, use bidi isolation and logical CSS, and keep the German shell LTR. Computed `font-family` alone is insufficient evidence. Static corpus translation can remain deferred; glyphs, shaping and RTL for feedback that ships cannot.
