## S5A package and media boundary (frozen)

Add objective interaction `fixed_audio`. Its public payload is exactly `{recordings:[{id,mediaId,mediaVersion,label,questions:[{n,question,options}]}]}`. IDs and question IDs are unique within a set, each question has at least two string options, all question IDs are flattened in recording order for existing marking. It contains no script/transcript/answer/explanation. Each recording references exact media identity; repeating one exact media in a form is rejected. Public instructions/labels are German, technical names English.

A media-required blueprint part uses fixed_audio and adds `playback:{practice:1,mock:1}` (DTZ), or its telc allowance 1/2/2 respectively. Both values are bounded positive integers; target-package policy cannot be weakened by arbitrary manifests. A listening form adds `attemptMode:'practice'|'mock'`, independent from `mode:'untimed'|'timed'`. Existing non-listening forms retain their bytes and behavior. New DTZ listening has 4 parts, 20 items (4/5/8/3); telc has 3 parts, 20 items (5/10/5). Source verification remains format research, not approval.

Package optional `media` contains `{mediaId,version,examId,path,sha256,byteLength,durationMs,mimeType,reviewStatus,rightsStatus,source}`. Paths are safe relative POSIX paths under the fixed private `content/exams/` root; no URL, absolute path, backslash, traversal, symlink escape or public/assets location. Supported initial audio is PCM WAV (`audio/wav`) with its actual parsed byte length/duration matching metadata; additional codecs need validated duration handling. Bounds: 32 MiB and 3600000 ms. The importer reads and verifies actual bytes before its transaction, with optional explicit `mediaRoot` for synthetic checks. New media imports are generated/unreviewed only. Approval requires separately attributable exact-version content/rights decisions. Media is immutable and linked to `content_version`; learner role can read metadata but cannot write it. Do not put protected transcripts or disk paths into public manifest/DTOs. Schema 0029-fixed-media.sql owns `exam_media(media_id,version,exam_id,path,sha256,byte_length,duration_ms,mime_type,content_version_id)` with exact identity/foreign keys and immutable trigger. Unique(media_id,version,exam_id). Public manifest projects media to identities/hash/length/duration/mime/review/provenance, excluding path.

`readReleasedForm` resolves fixed_audio sets, exact media and part playback allowance, applying rights/publication policy. Each member adds `recordings:[{id,media_id,media_version,label,duration_ms,mime_type,max_plays}]`; no path or protected text. Bundle adds `media` with database metadata for server-only use. Refused media blocks new starts; exceptional rights block hides protected content on resume but retains learner responses. Existing public-policy checks cannot be bypassed via listening IDs. Stateless standalone objective routes remain unable to answer listening; saved listening forms are the sole entry.

## S5A playback and routes (frozen)

One durable playback record per `(owner,run_id,media_id,media_version)`; recording identity and allowed count resolved from pinned form, never client policy. Playback revision is independent of mock_run revision so progress does not race answer autosave. Migration 0030-listening-playback.sql creates owned playback/event tables with FORCE RLS, deletion permissions, owner/run/media foreign keys, immutable identity and protected state transitions. Run lock order remains owner advisory lock, preparation, run, playback. Export includes playback progress without transport tokens; deletion removes events/playback before run and rejects late mutations.

`GET /api/v1/mock-runs/:runId/playback` returns `{items:[PlaybackDTO]}`. PlaybackDTO: `{media_id,media_version,revision,state,plays_used,max_plays,position_ms,duration_ms,playback_id,uncertain,server_now}`. State is `ready|playing|paused|completed`. For missing rows return ready revision 0, plays_used 0 and null playback_id. Reading never consumes or restarts. If last acknowledged state was playing after return, expose uncertain=true and conservative resume position capped at duration. Explicit recovery required.

`POST /api/v1/mock-runs/:runId/playback` accepts exactly `{eventId,mediaId,mediaVersion,expectedRevision,action,positionMs?,playbackId?}`. Actions: `begin`, `checkpoint`, `pause`, `complete`, `recover`. `begin` only after actual ready media and user play; creates next playback UUID and consumes one allowance atomically. A completed telc recording may begin its permitted next play; DTZ cannot. `checkpoint` and `pause` require current UUID/revision and monotonic bounded position. `complete` closes that play. `recover` explicitly acknowledges uncertain/saved progress, rotates UUID to fence other documents, resumes the SAME consumed play at the authoritative position (no new allowance). Idempotent event receipt returns current safe state; changed body under same ID conflicts. Stale revision/UUID conflicts; negative/backward/oversized progress refused. If a begin response is lost, retry exactly its event; never create another begin. Before any acknowledged begin, failed loading or rejected play leaves allowance unused. If consumption is uncertain, preserve recovery state, not a compensating refund/restart.

Recovery uses the last acknowledged position plus server elapsed time only while state=playing; a paused position stays fixed. This is conservative and may skip an uncertain interval; explain that honestly, never claim proof of what was heard. Do not silently return to zero after a started play. Explicit recover at end marks completed, without new allowance. Once started, refresh, tab/device return, mode switch and byte ranges cannot grant a fresh play. This is preparation UX enforcement, not DRM/proctoring.

`GET|HEAD /api/v1/mock-runs/:runId/media/:mediaId/:version` serves only pinned, owner-authorized media; no public/static equivalent. Recheck session, enabled package, active preparation/run, deadline, publication/rights, membership and full checksum before sending headers. Preloading/range requests do not consume. Accept one valid byte range (including suffix/open-end); return 206 with correct Content-Range, 416 invalid/unsatisfiable, accurate Content-Length/Type, Accept-Ranges, immutable checksum ETag and Cache-Control private,no-store. Do not leak filesystem names or provider details. Load bytes through bounded integrity-checked private file helper; stream route lives in owned API/session boundary. A stream already delivered cannot be revoked retrospectively; next request/mutation rechecks policy. Same account-generation checks apply to media as other private data.

POST returns `{playback:PlaybackDTO}`; GET media is binary. Errors use existing redacted envelope: `playback_conflict`, `playback_exhausted`, `playback_recovery_required`, `media_unavailable`, `media_integrity`, plus existing not_found, mock_expired/finalised/rights_blocked and preparation_archived. No keys/transcripts in any response.
