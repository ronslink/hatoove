# EXAM-S1: preparations and exam-specific credits

Working implementation contract for issue104, based on merged EXAM-S0. No production deployment, content approval or complete mock release is implied.

## Routes and client context

- Preparation DTO: {id, exam_id, exam, exam_language, exam_date:null|YYYY-MM-DD, state:'active'|'archived', revision, created_at, updated_at}. Stable exam identity, no blueprint pin; UUID id, owned by verified session. Unique active(owner,exam); revision guards edits.
- GET /api/v1/exams returns {exams:[{exam_id,exam,exam_language,level}]} for explicitly enabled packages. S1 exposes telc only, subject to existing deployment content policy. Adding a DB exam row must not publish another package. A strictly server-side injectable test catalogue may enable a second synthetic package in disposable tests; no client flag or live DTZ release.
- GET /api/v1/preparations returns {preparations:[DTO]} including archived history. POST /api/v1/preparations {examId} returns DTO (201 new/200 existing), idempotently returns active preparation without date overwrite and NEVER grants/refills credits. Existing upgraded users and newly registered users have a telc preparation; root skips single-option chooser. A genuinely empty account may explicitly POST when only one package is available.
- GET /api/v1/preparations/:id returns DTO. PUT same path {expectedRevision,examDate?,state?} returns updated DTO. Stale=>409 preparation_conflict (safe current DTO), foreign/absent=>404; real date validation, exam identity immutable. Archived history and pending jobs remain readable/finishable; no new practice in archived preparation. Resume state change does not mint credits; reject conflicting second active prep.
- GET /api/v1/preparations/:id/credits => {examId,allowance,used,reserved,available}; an absent exam balance is zero, not a new grant.
- Require preparationId query on GET tasks, objective-sets list/read, practice/next, practice/progress, practice/mistakes and attempts list (including open=1). Objective answers and new writing attempts require preparationId in JSON. Missing/invalid=>422 preparation_required/invalid_preparation, foreign/absent=>404, wrong-exam content/binding=>422 preparation_mismatch BEFORE writes. Any retained exam query may only equal the resolved preparation exam. Never default missing context to all exams or telc just to preserve old tests. Shared vocab/nouns/guides remain reference routes outside prep scope in S1.
- Existing attempt/submission ID read/save/submit/result/retry/delete derive their immutable context from the owned record. Parent revision inherits exact parent's prep/exam and rejects an explicitly different prep. New unbound writing attempts must have preparationId; retain the exact selected task/rubric four-field binding, with a package-safe default only if existing contract still supports it.
- Attempts/results/history expose preparation_id/exam_id. Catalogue queries/progress/mistakes filter by that context; no cross-prep evidence. Credits are keyed(owner,exam), never prep. Account export includes ALL preparations/history/balances, including archived/retained data. Hard account delete includes all new private records and late-job negatives.
- Account theme/language remain account preferences. Preparation owns the active date. Preserve old settings.exam_date storage for audit/export; do not overwrite that retained legacy value during prep edits. /settings should no longer accept examDate for current writes; root moves date UI to preparation. Do not expand daily-goal feature scope.

## Safe migration and ledger

One forward migration0023: create learner_preparation with FORCE RLS and narrow learner/worker/deletion policies/grants. Backfill users and existing identifiable telc work with preserved stable IDs; derive task/rubric/exam from exact historical records, never from a global preference alone. Existing telc corpus is provable; ambiguous rows remain nullable/unresolved and readable, with explicit count/report rather than guessing. Add prep/exam columns/FKs on attempts and item_evidence with composite owner/exam consistency. Never alter immutable submitted text/result snapshots or disable their triggers. Derive submission/job identity via immutable attempt. Add SQL protection against cross-exam content tuples for new writes, not API checks alone.

Extend entitlements PK to(owner_id,exam_id), preserving EVERY old allowance/used/reserved into telc exactly; new prep never changes balance. Scope all reservation, retry, success debit, failure release, timeout/reclaim refund and deletion locks to original exam. Update usage ledger identity consistently (may derive retained identity via immutable attempt if preferable); no old transaction/assessment rows lost. Lock consistently to avoid deadlocks. New second synthetic exam has no grant unless test provisioning explicitly supplies one. Do not add payments or commercial prices.

RLS backfill must work under real migration role: narrowly scoped temporary migration policies in its transaction or explicit per-owner context, not disabling learner isolation. Existing historical exam_date values were regex-only validated: preserve raw originals and backfill only VALID calendar dates; invalid dates remain preserved with explicit disposition, no migration crash. Do not fabricate completed mocks from old answers.

Registration defect: initial preparation and exam credit provisioning must be part of the auth transaction, not a post-COMMIT insert. Use a narrow SECURITY DEFINER provisioning function with fixed search_path, no PUBLIC execute and auth-only call, no broad runtime privilege. Idempotent insert-only grant must not refill existing balances. Inject provisioning failure and prove account/session/entitlement/prep all roll back. Update misleading auth/provision comments if touching them; no unrelated auth redesign.
