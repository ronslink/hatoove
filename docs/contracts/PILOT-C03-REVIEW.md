## Identity and authority

Forward migration0035 adds append-only `content_review_authority` and `content_review_decision` ledgers. Events have UUID identity, canonical request digest, positive revision, exact expected predecessor, one-successor and replay constraints, database time and operator role. Authority streams are `(reviewer_id,exam_id,category,language)` with no wildcard; events grant or revoke. Store snapshotted human name and bounded qualification/appointment evidence reference+digest and rationale. Categories are educational, language, audio and exam_format; educational/format language is empty, audio is the exam language, translation scope is de/en/uk/ar/tr.

This is an operator-recorded human attestation, not authenticated reviewer login or a verified digital signature. Owner-established appointment/qualification evidence is a prerequisite to real use. No real authorities are seeded. One authorized decision per required category is the initial engineering quorum; any stronger human reviewer independence/quorum policy must be decided before real approval, without silently broadening this engine.

Decisions approve, reject or withdraw one exact content version, blueprint version or form version. Typed FKs/checks prevent multi-target records. Resolve actual exam and source digest from existing immutable rows; compare expected digest, never infer identity by splitting an @ string or accept caller-selected SQL. Decisions include exact granting authority event, evidence reference+digest, rationale and optional private packet digest. Set approval covers the complete set including keys; format review covers counts/order/timing/choices/playback, not its members. Media review verifies actual bytes through the existing integrity reader. A changed source requires a new identity/hash and review.

Current heads follow revision/predecessor chains, never timestamps. Each write checks expected authority and decision heads after fencing. Same event and canonical bytes replays the original receipt even after later revocation; changed-payload reuse conflicts. Stale heads cannot auto-rebase or branch. Revoking authority is future-only; prior valid decisions remain until explicit subject withdrawals. Runtime roles cannot appoint reviewers, record decisions, alter heads or read private evidence.
