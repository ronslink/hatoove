# EXAM-S2 implementation contract

Execution EXAM-S2-20261003-A, issue107, base3a010e6. This document is the coordinator-owned frozen interface for the minimal package and saved reading section slice. No educational approval is granted.

## Content and publication

Version-controlled input lives in content/exams/<exam-id>/. The import command reads one JSON document `{schemaVersion:1, exam:{id,title,language,levelModel}, blueprint:{version,sections,assessment}, release:{version,state,resumeBlockedReleases:[]}, forms:[], sets:[]}`. `state` is hidden/internal/available/withdrawn. `sets` is optional for new exact objective content; existing references remain immutable. Exam language, level model and objective assessment scale are data, not German constants. The initial telc blueprint records all written sections and the shared reading/language timing, but its first form is reading only.

Each form is `{id,version,title,scope:'section',sections:['LV'],mode:'untimed',timeLimitSeconds:null,feedback:'finalise',members:[{setId,version,interaction,itemCount}]}`. Supported S2 interactions are matching_headlines, single_choice, matching_ads, gap_choice and gap_bank; the first form uses the first three. Versions are explicit strings matching v plus digits. Complete-supported-written forms are rejected in S2; they require the later reviewed media/writing contract. Unsupported shapes fail closed. DTZ may only become available with all written sections and all exact review/rights/media gates passing together; partial fixtures are offline/internal only. The server retains its explicit telc-only enabled-exam boundary for learner routes in S2.

A new objective set imports `{setId,version,examId,family,section,part,title,payload,itemCount,interaction,answers,explanations,reviewStatus,rightsStatus,source}`. The importer validates exact item IDs/options/keys, no secret fields or protected transcripts in public payload, known interaction shape, same exam/blueprint, counts and unique membership. Protected answers/explanations go only to objective_key. Publisher rights use the existing privileged migration role via a dedicated CLI, never a browser endpoint/runtime pool. Dry-run validates database references and produces a diff without mutation. Identical canonical content under the same identity is idempotent; different canonical bytes under an existing version fail atomically. Hashes, publisher and timestamp produce an audit receipt. Existing migrations/content/provenance are never rewritten. New package imports do not grant learner availability or credits by themselves.

Tables supplied by coordinator in migration0024:
- exam_blueprint(exam_id, version, payload jsonb, sha256, imported_at), PK(exam_id,version).
- exam_release(exam_id, version, blueprint_version, state, manifest jsonb, sha256, publisher, imported_at), PK(exam_id,version), blueprint FK.
- exam_form(exam_id, form_id, version, blueprint_version, payload jsonb, sha256, imported_at), PK(exam_id,form_id,version), blueprint FK.
- exam_form_member(exam_id, form_id, form_version, position integer zero-based, set_id, set_version, interaction, item_count), PK(exam_id,form_id,form_version,position), unique member tuple, exact same-exam objective_set FK and form FK.
- exam_release_form(exam_id, release_version, form_id, form_version), exact release/form FKs and composite PK.
- exam_release_head(exam_id PK, release_version), exact release FK. This sole mutable publication pointer is privileged; runtime SELECT only.
All are shared content, runtime SELECT only; all except head have immutable triggers. Blueprint/form payloads and release manifest contain no keys. Releases never use lexical latest-version selection. Internal releases require deployment internal-preview plus existing content/rights policy. Available requires qualified exact-version approvals; agents cannot fabricate these. New starts require the active nonwithdrawn permitted release. Existing pinned runs survive ordinary withdrawal. If the current head's manifest.release.resumeBlockedReleases includes their pinned release version, their protected content and finalisation are blocked with an explicit rights-blocked state; retained responses/identity remain readable and exportable. No content substitution.

## Owned run contract

Backend worker owns migration0025 and server/mock-contract.mjs plus server/owned-postgres/mock-runs.mjs, adapter and owned API integration. New mock_run table stores owner, preparation, exam, exact release/blueprint/form versions, revision, start event ID, state active/finalised, saved responses, position, timestamps/deadline and immutable result. Use composite same-owner/exam/preparation and exact release/form FKs; force RLS with learner ownership and deletion role. SQL protects identity and finalised snapshots. No old evidence is turned into runs. No S2 writing children, jobs, debit or credit changes.

Routes and datastore methods (camelCase arguments, snake_case row DTOs):
- GET /api/v1/mock-forms?preparationId=UUID => `{forms:[{exam_id,release_version,blueprint_version,form_id,version,title,scope,sections,mode,time_limit_seconds,item_count,review_status}]}`. `listMockForms(owner,{preparationId})`.
- GET /api/v1/mock-runs?preparationId=UUID => `{runs:[summary]}` newest first, bounded. `listMockRuns(owner,{preparationId})`.
- POST /api/v1/mock-runs `{preparationId,formId,formVersion,releaseVersion,eventId}` => full run DTO, 201 new /200 identical retry; event UUID unique per owner, conflicting payload409. `startMockRun(owner,{...})` returns `{created,run}`.
- GET /api/v1/mock-runs/:id => full owned DTO, 404 cross-owner. `readMockRun(owner,id)`.
- PUT /api/v1/mock-runs/:id `{expectedRevision,eventId,responses,position}` => full DTO. `saveMockRun(owner,id,{...})`. `responses` is a bounded array `{setId,version,itemId,answer}`; full snapshot, exact form items only; answers valid offered scalar values or null, no duplicate tuples; position `{member:0,item:0}` valid bounds. Revision starts1 and increments each save. Same save event/body returns the saved result or a current-safe acknowledged DTO on retry; reused event with different body409. Stale different-event revision409. No client owner/exam/mark fields accepted.
- POST /api/v1/mock-runs/:id/finalise `{expectedRevision,eventId}` => full DTO. `finaliseMockRun(owner,id,{...})`. Lock preparation then run consistently with archive. Atomically freeze saved answers, mark all items once, append version-exact item_evidence for answered items only, store per-item result including explicit unanswered plus counts. Duplicate finalise returns the existing finalised snapshot (never duplicate evidence), stale unfrozen revision409. Saves after finalise409 even with obsolete retries; finalised reads preserve exact snapshot. A retake uses a new start event and new run ID.

Full DTO: `{id,preparation_id,exam_id,release_version,blueprint_version,form_id,form_version,title,scope,mode,state,revision,responses,position,created_at,updated_at,deadline_at,finalised_at,expired,blocked_reason,members,result}`. members are ordered `{set_id,version,interaction,item_count,title,family,section,part,payload}` from pinned content; no correctness/explanations while active. result null while active, otherwise `{items:[{set_id,version,item_id,answer,correct,unanswered,correct_answer,explanation}],answered,unanswered,correct,total}` (objective marks/counts only, no overall grade/pass). Include server_now to render deadlines safely. Ordinary rights-block state retains DTO identity/responses but members empty and result hidden if protected. Archived prep reads retain history, writes409. Optional form timeLimitSeconds pins a server deadline at start; expired saves refuse and retain last saved data, finalise grades only acknowledged answers and reports expired, no clock reset on refresh. Initial live form is untimed; deadlines are tested with synthetic fixture.

Export adds mock_runs under the repeatable-read account export, preserving original runs/responses/results. Account deletion removes all new owned rows; classifier and RLS/deletion negatives cover them. Idempotency storage is owned and included in deletion but transport receipts are not learner content. Read/write API paths use existing session/account fencing and origin/body validation. No runtime fallback to default prep/form/version.

## Client

Vanilla mock.js controller with api.js sole URL owner; bounded app.js hooks and index/CSS integrate a section-practice entry, saved run list, start/resume/new retake, exact members/answers, saved status, unanswered/finalise confirmation and post-finalise factual result. Prioritise saved run resume on Heute; expose history with original exam/form label. Use existing orange/warm-paper design and German interface. Preserve old writing/standalone flows. No browser persistent state. Save before changing part/view/preparation, retaining current answers and recoverable view after conflict/lost response/session failure. Serialize saves; stable event retries; fence obsolete reads. Recovery lets learner retry same uncertain operation or explicitly reload server data while preserving/copying local answers. Deep run links resolve original owned preparation. No feedback or explanation before finalise, no assistance automatically applied. Refresh/new session resumes server-acknowledged state.

## Publisher command

The migration service imports the bundled telc manifest idempotently after forward migrations. Runtime API/worker roles cannot publish. For an explicitly selected disposable or authorised installation, the existing Compose migration service can validate the exact bundled source with:

```text
docker compose run --rm --no-deps migrate node tools/import-exam-package.mjs content/exams/telc-deutsch-b1/manifest.json --dry-run
```

The receipt contains exam/release, canonical SHA-256, publisher, planned changes and `unchanged`. Removing `--dry-run` applies a separately authorised publication transaction; it does not grant content approval or enable a new runtime exam. New versions are required for changed source. Forms must fit both 500 responses and the API's 64 KiB JSON body limit, including the largest offered answers encoded as UTF-8. The image contains only this tools-directory command and the bundled `content/exams` sources, never synthetic fixtures.
