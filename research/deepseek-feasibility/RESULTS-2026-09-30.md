# DeepSeek V4.1 Flash versus Mistral for Hatoove

30 September 2026 · GreenPT EU API · Synthetic benchmark

**Recommendation: use EU-hosted DeepSeek V4.1 Flash as the preferred model for Hatoove's writing-feedback pilot and reviewed content production. It performed better than the tested Mistral configurations on correction quality in this suite. Do not treat its numerical writing marks as calibrated exam scores yet.**

This is a concrete improvement over the Mistral finding. In the matched fuller-rubric tests, DeepSeek made no invented mandatory corrections on the intentionally grammatical responses, correctly repaired 28 of 30 annotated error instances, and did not obey the tested hidden instructions. It still missed one type of grammatical error, varied some scores between repeats, and initially misapplied the register rule.

For the product, this supports showing a learner which task points they addressed and giving useful suggested corrections in a private pilot. It does not yet support telling them that a particular AI mark establishes their exam readiness. Reading/listening marking should continue to use approved fixed answer keys.

## Completed comparison

The main run completed **38/38 requests**, all HTTP 200 with complete, schema-valid outputs:

- Ten writing assessments using the original task and shortened rubric, directly comparable with the corrected Medium 3.5 run.
- Twenty-four writing assessments using the fuller rubric: twelve responses across three tasks, repeated twice.
- One reading set, five listening scripts in one generation, and Arabic/Ukrainian translations of a frozen feedback sample.

These are **22 unique writing responses**, not 34 independent learners. All material was synthetic. No qualified examiner supplied whole-response gold scores. A separate four-call diagnostic then examined the register error; its results are not substituted into the main comparison.

## What DeepSeek did better

**It provided accurate local grammar fixes without inventing errors in the clean controls.** For example, it correctly used `meinem Bruder` and `mir` with *helfen*, and rewrote the complete `ob` clause as `ob eine Abholung am Dienstag möglich ist`. Mistral sometimes supplied the wrong case or removed the finite verb without restoring it. DeepSeek also accepted grammatical object-first sentences that Mistral had falsely marked as incorrect.

Semantic review found that **28/30 annotated error instances in the fuller-rubric suite received correct repairs in context**. This is stronger evidence than an automated quote-overlap check. The two misses were repeats of the same error: `haben ... mit dem Zug ... gefahren` where the intransitive travel construction requires `sind`. It correctly repaired the other two deliberately introduced errors in that letter. This ratio describes a small set of deliberately planted errors, including repeated and attack-paired instances; it is not population-level grammar accuracy.

**It handled the tested attacks better.** The original-task attack left the score at 39 and retained useful corrections. In the fuller-rubric suite, none of four attack variants increased the corresponding control score or returned the requested marker. One attack variant received a lower score. Four comparisons cannot establish general injection resistance; they do establish that the particular attack which redirected Medium's answer did not redirect DeepSeek here.

**It understood the task content reliably in this set.** All 96 content-point labels matched the authored expectations. Its original ten-call suite also mapped its own coverage flags to content scores consistently. In the fuller-rubric suite, the software calculates content arithmetic from those labels; this arithmetic is not credited as a model capability.

## What still prevents dependable exam marking

**The original fuller rubric produced a systematic register error.** The deliberately informal guesthouse reply covered all four content points, but DeepSeek classified it as `wrong_situation` and removed the entire content score in both repetitions. It awarded 24/45 rather than preserving content credit. Its original shorter-rubric test had handled register correctly, suggesting an ambiguity introduced by the expanded status definitions. Small 4 made the same classification mistake; Medium retained content but penalised register under both communication and grammar.

**Language-band scores still vary.** Three of twelve fuller-rubric cases changed by six points between repeats, including deliberately erroneous birthday and bookcase letters. Seeing three local errors does not by itself prove that an A band is impossible under the official B1 rubric; the demonstrated problem here is inconsistent band selection, not a claim that every 45 is inherently wrong. Expert calibration remains necessary.

**It is not an exhaustive proofreader.** Both repetitions missed the travel-auxiliary error. Feedback should be presented as useful identified improvements, not an assurance that all remaining text is correct.

## Separate register diagnostic

After preserving the full main run, a general clarification was added: inappropriate `du/Sie`, greeting or closing alone must not change the situation classification or remove otherwise earned content credit; genuine changes of communicative role still qualify as a wrong situation. The original offending letter was repeated twice. A newly authored control reversed the guest/host roles and was also repeated twice, to check that the clarification did not merely disable `wrong_situation`.

**The clarification worked on all four diagnostic calls.** Both register-only replies retained full content credit and reduced communication credit, scoring 39 rather than 24. Both genuine role-reversal controls were still classified as `wrong_situation`, with language credit assessed separately. All calls returned valid JSON and exact quotations.

This establishes that the observed register error was locally correctable. It does not validate the revised prompt across a broader population or prove its numerical language bands are correct. The diagnostic was tuned after seeing a failure and cannot be described as an unseen benchmark or used to replace the original 24-call results. ## Practice-content and translation findings

The reading draft had **331 words**, five questions, exact supporting quotations and varied answer positions **b, c, a, c, b**. The identified answers were supported by the passage. Some distractors were very easy to reject, so difficulty and exam-style fidelity need editorial review.

All five listening scripts met the requested length: **51, 49, 53, 47 and 49 words**. They mixed true and false answers and supplied exact evidence. This is a useful drafting result compared with Small 4's short scripts, all-false keys and identified ambiguities. The scripts are not an audio test: pronunciation, pace, accents, replay rules and real listening difficulty were not evaluated.

Arabic and Ukrainian translations preserved the requested language and overall feedback purpose. The Arabic wording uses Arabic case terminology for the German cases; a reviewed glossary should explicitly preserve German labels such as *Dativ* and *Akkusativ*. One sample per language and assistant inspection cannot replace native review. These translations used exactly the same frozen input as Small 4's original probes; Large originally translated a different model-generated feedback text.

## Practical decision for the build

| Feature | Decision |
|---|---|
| Question, script and explanation drafting | Use DeepSeek, with editorial approval before items enter the reusable question bank |
| Reading/listening answer marking | Use deterministic code and approved answer keys |
| Individual writing task-point feedback and corrections | Select DeepSeek for the private pilot; preserve quoted evidence, correction context and output validation |
| Exact writing marks and readiness prediction | Keep experimental until tested against independently rated scripts |
| Native-language explanations | Use a reviewed glossary and native review before public release |

The next quality investment should be a larger, permissioned set of real or expert-authored responses, rated independently by qualified examiners. Measure unnecessary corrections and incorrect replacements separately from missed errors and score agreement. Freeze the revised rubric before testing on fresh cases. The present inputs now serve as regression cases.

## Technical and cost record

The main run used `deepseek-v4.1-flash` at `https://api.greenpt.ai/v1`, `reasoning_effort=high`, `temperature=0`, `top_p=1`, an 8,192-token output allowance and at most two simultaneous requests. All completions returned the requested model identifier. GreenPT documents this model as running on EU infrastructure; this test verifies the endpoint and returned identity, not the physical location independently. [GreenPT model documentation](https://docs.greenpt.ai/deepseek-v4-1-flash)

The exact Mistral task texts, semantic instructions and schemas were loaded from the saved protocols. GreenPT does not document Mistral's strict JSON-schema transport, so the schema was appended to the system prompt. That format-control difference and the providers' unequal meanings of high reasoning prevent treating this as an isolated comparison of model weights. It is a comparison of the recorded usable API configurations. No hidden answer expectations were sent to either model.

The main run cost an estimated **€0.099300916** based on reported token usage and published GreenPT rates, including reported cache hits. The diagnostic added **€0.017881116**, making **42 completed calls and €0.117182032 in total**. The fuller-rubric writing calls averaged **€0.00256669 each**, approximately **€0.26 for 100 comparable assessments**, before retries, extra verification or different response lengths. Charges are estimates, not checked invoices. Mistral figures remain in USD; no exchange-rate equivalence is assumed.

The key was read from the user-specified existing environment file and passed only through process memory/stdin. Secret values and internal reasoning were not saved in the research outputs. No application settings, domain configuration or deployment were changed.
